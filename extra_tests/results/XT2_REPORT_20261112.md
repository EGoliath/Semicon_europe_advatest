On one core the container is 3x smaller **and compresses 3–4x faster** than zstd -9, but decodes ~3.5x

## What each experiment showed (subset of 7 files unless stated)

| experiment (report ID) | result | verdict |
|---|---|---|
| profiler (rank 1) | 20–96% distinct rows on big files; up to 43% rows = previous row; 38–67% duplicate pins on 128/192-pin files | row dictionary: not worth it |
| zstd level × `--long` on raw (T2/T4) | `-12` 1.07x, `-19` 1.50x (14 MB/s), `-19 --long=27` 1.52x, `-3 --long=27` **0.86x (worse)** | standard-format ceiling ≈ 1.5x |
| block-independence cost (T5) | 16 Mi rows +0.1%, 4 Mi +0.9%, 1 Mi +2.3% vs one block | independent blocks are almost free |
| explicit constant/duplicate/complement planes | 192-pin files keep 64 of 192 planes, 128-pin keep 64 | main reason `--long` is no longer needed |
| per-plane XOR by trial (`x`) | never chosen (no plane >3% better) | rejected |
| row-repeat bitmap (`r`) | +7.7% larger (breaks periodic matches) | rejected |
| zstd params on the plane stream (minMatch, btultra2, targetLength, searchLog) | best −0.15% | zstd is saturated; rejected |
| level 22 vs 19 in blocks | identical size, slower | rejected |
| pin-group task frames (`g`) | 007: compress 141 → 856 MB/s, size −0.9% | kept (all finalists) |
| E8 fallback to plain zstd | used on 2 tiny files (001, 015) | kept |

## Container (as built)

Header: W, rows, per-pin symbol table + block index (zstd-19 compressed, counted in the size).
Per block of R vectors: per plane `ZERO / ONES / COPY q / NOT q / STORED / STORED_X`; stored planes
split into pin-group frames (2 per inner thread), each an independent zstd frame (LDM, window = frame).
Encode/decode: two-level OpenMP (blocks × frames); decode writes rows straight to their fixed offset
in a preallocated MADV_HUGEPAGE buffer.
